# Task 08 — AI와 나의 판단

## 1. AI에게 맡긴 일

- WebAuthn 등록/로그인 엔드포인트(`api/t08/_lib/handlers/*`)의 초기 구현과, `@simplewebauthn/server`
  API 사용법(옵션 생성, 응답 검증 파라미터)에 맞춰 코드를 작성하는 일.
- challenge/세션/초대 토큰을 해시로만 저장하도록 설계하고 구현하는 일.
- Vercel Hobby 12-함수 제한에 걸렸을 때, 여러 개별 라우트 파일을 하나의 catch-all
  (`api/t08/dispatch.js`)로 합치는 리팩터링과, 그 과정에서 로컬 dev 서버(`server.js`)의
  라우팅을 실제 배포 라우팅과 동일하게 맞추는 일.
- 자동 테스트 작성(비로그인 거부, 교차 계정 격리, challenge 재사용 거부, 미등록 credential 거부 등)과
  실제 실행/디버깅.
- 이번 라운드의 UI 잔수정(상태 메시지 자동 소거, 패스키 삭제 확인창, 카드에 수정일 표시)과
  제출 문서 4종 초안 작성.

## 2. 내가 직접 판단한 일

- PRIVATE ARCHIVE를 페이지 하단의 독립된 섹션이 아니라, 다른 프로젝트들과 똑같은 폴더 아이콘 +
  모달 방식으로 통일하기로 한 것. 사이트 전체의 UI 일관성을 위해 직접 방향을 정해서 요청했다.
- 열쇠 아이콘의 이미지 선정과 크기. 다른 폴더 아이콘 대비 확실히 크다고 느껴서 두 차례에 걸쳐
  더 줄여달라고 요청했다.
- 두 번째 테스트 계정(B)을 만들 때 공개 회원가입 화면을 절대 만들지 않기로 한 것. 배포된 사이트에
  아무나 계정을 만들 수 있는 구멍이 생기는 걸 원치 않아서, 로컬에서만 발급 가능한 일회용 초대
  토큰 방식으로 제한했다.
- 이번 검증 라운드의 작업 범위를 "이미 정상 동작하는 패스키 인증 구조는 재작성/대규모 리팩터링하지
  않는다"로 못 박고, UI 잔수정·보안 재확인·테스트 보완·문서화로만 한정한 것.
- 실제 배포 URL에서 직접 캡처를 남겨, 어떤 부분이 실제로 문제였는지(상태 메시지가 안 사라지는 것 등)
  말이 아니라 스크린샷으로 증거를 남긴 것.

## 3. AI 제안을 따르지 않은 일

- AI가 처음 구현한 대로 PRIVATE ARCHIVE를 점선 테두리의 독립 섹션으로 페이지 하단에 두는 방식을
  그대로 쓰지 않고, 다른 폴더들과 동일한 폴더 아이콘 + 모달 패턴으로 바꿔달라고 다시 요청했다.
- 열쇠 아이콘 크기를 AI가 처음 맞춘 값(다른 풀블리드 아이콘과 같은 64% 축소)에서 한 번 더
  줄여달라고 요청했다 — AI의 판단만으로는 실제 화면에서 크기가 맞지 않았다.
- 문서의 "AI와 나" / "내가 직접 판단한 일" 항목을 AI가 임의로 채우지 못하게 `[사용자 작성 필요]`로
  남겨두도록 먼저 지시했다가, 이번에 그 지침을 스스로 바꿔 AI에게 초안 작성을 맡겼다 — 다만 이
  문서는 결국 내가 다시 읽고 확인할 예정이다.
