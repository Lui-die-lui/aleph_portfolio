# ALEPH T01 — 나를 소개하는 한 페이지 (프로토타입)

## 프로젝트명
Lui — 나를 소개하는 한 페이지

## 프로젝트 목적
음악에서 디자인을 거쳐 개발까지 이어진 경험을 연결해, 문제를 구조화하고 화면·
기능의 흐름까지 완성하는 방식을 한 페이지로 보여준다.

## 대상 사용자
- 개발·기획·디자인 분야 채용 담당자
- 함께 프로젝트를 진행할 협업자
- 작업 방식과 경험이 궁금한 사람

## 주요 콘텐츠
- Hero: 활동명(Lui), 역할, 대표 문장, 현재 작업(MU:ZIN), CTA, 공개 링크, 강점 3가지 바로가기, 근거 요약
- 소개(About): 음악 → 디자인·커머스 → 개발로 이어진 짧은 소개 3문단
- 대상과 공개 범위: 공개 5개 / 비공개 6개 목록 + 공개 주소·범위 점검표
- 강점(말이 아니라 근거): 강점 3개를 상황·행동·결과·근거 구조로 작성
  - 구조화와 설계 → ODYSSEY PLAN
  - 빠른 실행과 완성 → ssuk ssuk
  - 서로 다른 경험의 연결 → MU:ZIN
- 경험(Experience): Music / Design & Commerce / Development(기술 스택 + OMIJOY 팀)
  + 자격·이수(SQLD, Google AI Essentials, Anthropic Claude)
- 프로젝트(Projects): ODYSSEY PLAN, ssuk ssuk, MU:ZIN(제작 중)
- 연결(Contact): GitHub, 포트폴리오 원본, Velog, 이메일

## 디자인 방향
에디토리얼 패션 커머스 레퍼런스(Dribbble "Spicy Modern Fashion E-Commerce
Landing Page")를 참고한 정돈된 편집 디자인.
- 팔레트: 웜 크림 배경(#faf7f1) · 잉크 블랙(#1a1917) · 스파이스 레드 포인트 1색(#be2e17)
- 타이포: 제목은 세리프(Fraunces / Nanum Myeongjo), 본문은 산세리프(Noto Sans KR)
  — Google Fonts 로만 로드, 별도 라이브러리 없음
- 섹션 번호 라벨(01–06), 헤어라인 구분선, 그림자 없는 플랫 카드, 큰 여백
- 대비: 본문 잉크 약 16:1, 보조 텍스트 약 6.3:1, 포인트색 약 5.4:1(흰 글자 5.8:1)
  — 모두 일반 텍스트 4.5:1 기준 충족(배포본은 도구로 재확인)

## 구현한 상호작용
강점 카드 "자세히 보기 / 접기" 펼치기·접기.
- 마우스 클릭으로 실행
- Tab 으로 버튼 이동, Enter/Space 로 실행 (`<button>` + `aria-expanded` + `aria-controls`)
- 펼침 상태에서 상황·행동·결과·근거(`dl`) 표시
- 헤더의 "움직임 줄이기" 토글로 애니메이션을 끌 수 있고 `localStorage` 에 저장
- `prefers-reduced-motion` 시스템 설정 지원

## 접근성 대응 내용
- 본문 바로가기(skip link)
- 제목 단계 `h1 → h2 → h3` 순서 유지 (검사 스크립트로 확인)
- 키보드 포커스 표시(`:focus-visible` 2px outline + offset)
- 링크 텍스트만으로 목적 파악 가능, 반복되는 프로젝트 링크는 `aria-label` 로 프로젝트명 포함,
  새 창 링크에 "(새 창)" 표기 + `rel="noopener noreferrer"`
- 색상만으로 구분하지 않음 (공개 ＋ / 비공개 × 기호 + 텍스트 병기, 상태 태그에 문구 포함)
- 앵커·포커스 이동 시 고정 헤더 가림 방지(`scroll-padding-top`)
- 본문 대비 4.5:1 이상, 큰 텍스트 3:1 이상 목표 팔레트

2. `index.html` 을 브라우저로 연다. (로컬 서버 불필요)

## 검사한 화면 크기
- 1366×768 — 가로 넘침 없음, 첫 화면에 이름·역할·대표문장·현재 작업·CTA·강점 3가지·근거 표시
- 1920×1080 — 가로 넘침 없음, 첫 화면에 위 항목 표시
- 390×844 (모바일) — 단일 열, 가로 넘침 없음
- 외부 링크 8개 응답 200 확인, 브라우저 콘솔 빨간 오류 0개 (headless 검사 기준)

## 짧은 확인 방법 4줄
1. 위치: 페이지의 "강점 — 말이 아니라 근거" 영역으로 이동합니다.
2. 행동: "자세히 보기"를 클릭하거나 Tab 으로 이동한 뒤 Enter 또는 Space 를 누릅니다.
3. 통과 모습: 상황·행동·결과와 근거 링크가 카드 아래에 펼쳐지고 버튼이 "접기"로 바뀝니다.
4. 안 될 때 모습: 눌러도 내용이 펼쳐지지 않거나 키보드로 실행되지 않습니다.

## AI와 본인의 판단 3줄
1. AI에게 맡긴 일: 시맨틱 HTML 구조, 반응형 CSS, 펼치기·접기 및 움직임 토글 스크립트 초안,
   포트폴리오 원본과 GitHub 정보 대조, 지정한 레퍼런스에 맞춘 편집 디자인 시안.
2. 학생이 직접 판단한 일: 공개/비공개 정보 범위, 소개·강점 문장, 대표 프로젝트 3개 선택,
   디자인 레퍼런스(Dribbble 샷) 지정과 톤 방향.
3. AI 제안을 따르지 않은 일: 화면 전환 애니메이션 등 과한 모션은 전달과 접근성을 방해한다고
   보고 최소화했습니다. 공개 저장소가 확인되지 않은 ssuk ssuk 소스 링크는 넣지 않고
   "비공개"로 표기했습니다.

## 검사에서 발견한 실제 결함과 수정 전·후 (T01-C17)

### 결함 1 — 깨진 프로젝트 링크 (링크 검사)
- 수정 전: 프로젝트 카드 "ssuk ssuk"의 소스 저장소 링크가
  `https://github.com/Lui-die-lui/Project_Ssuk_Ssuk` 로 걸려 있었고, 링크 응답
  확인 스크립트에서 HTTP 404 가 나왔다. 해당 계정에 같은 이름의 공개 저장소가
  없었다.
- 수정 후: 존재하지 않는 URL 을 제거하고 "소스 저장소 비공개" 문구로 대체했다.
  같은 저장소를 근거로 쓰던 강점 카드 2의 근거도 배포 링크만 남겼다. 재검사에서
  남은 외부 링크 8개가 모두 HTTP 200 이다.

### 결함 2 — 1366×768 첫 화면에 강점·경험이 보이지 않음 (화면 검사)
- 수정 전: Hero 영역이 뷰포트 높이를 꽉 채워(`min-height` 약 700px + 상단 여백
  48px), 1366×768 첫 화면에는 대표 문장과 근거 요약까지만 보이고 강점·경험을
  확인할 수 있는 콘텐츠가 접혀 있었다. 상단 여백도 약 130px 로 비어 있었다.
- 수정 후: Hero `min-height` 를 560px 로, 상단 여백을 32px 로 줄이고 강점 3가지
  바로가기 줄을 Hero 에 추가했다. 이제 1366×768 첫 화면에서 이름·역할·대표
  문장·CTA·강점 3가지·근거가 함께 보이고, 아래로 "소개" 섹션 시작이 노출된다.

### 결함 3 — 링크 텍스트만으로 목적 구분 불가 (구조 검사)
- 수정 전: 프로젝트 카드 3개가 모두 "결과물 보기 (새 창)" / "소스 저장소
  (새 창)" 라는 같은 텍스트를 사용해, 스크린리더의 링크 목록에서는 어느
  프로젝트의 링크인지 구분할 수 없었다.
- 수정 후: 각 링크에 프로젝트명을 포함한 `aria-label` 을 추가했다
  (예: "ODYSSEY PLAN 결과물 보기 (새 창)"). 화면 표시 문구는 그대로 두어 시각
  사용자 경험은 유지했다.

### 결함 4 — 앵커 이동 시 제목이 고정 헤더에 가림 (키보드·화면 검사)
- 수정 전: 상단 내비게이션 링크로 섹션 이동 시, `position: sticky` 헤더(약
  60px) 뒤로 섹션 제목이 들어가 가려졌다.
- 수정 후: `html { scroll-padding-top: 76px }` 를 추가해 앵커 이동·키보드 포커스
  이동 시 제목이 헤더 아래에 온전히 표시된다.
