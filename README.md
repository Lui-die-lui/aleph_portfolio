# ALEPH T01 — 나를 소개하는 한 페이지

## 프로젝트명
Lee Seul gi — Portfolio

## 프로젝트 목적
음악에서 디자인을 거쳐 개발까지 이어진 경험을 연결해, 채용 담당자·협업자에게
근거와 함께 보여주는 한 페이지를 만든다.

## 대상 사용자
- 개발·기획·디자인 분야 채용 담당자
- 함께 프로젝트를 진행할 협업자
- 작업 방식과 경험이 궁금한 사람

## 화면 구조
Hero(첫 화면) + 폴더 4개 + 모달 4개 + 하단 연결(Contact)로 구성된 1페이지
구조다. 스크롤 없이 첫 화면에서 이름·타이틀·근거 요약·폴더가 모두 보이고,
각 폴더를 열면 모달로 상세 내용이 뜬다.

- **Hero**: 이름(Lee Seul gi), 타이틀(Portfolio), 대표 문장, 설명, 근거 요약 한 줄
- **폴더 4개**: About Me / Music / Dev·Projects / Web Design — 클릭하면 같은
  모달 컴포넌트에 내용만 바뀌어 들어간다
- **About Me 모달**: 페이지 목적 한 문장 + 강점 3개(상황·행동·결과 + 근거 폴더
  바로가기 버튼) + 공개 범위 점검표(접이식)
- **Music 모달**: 교습·연주활동·수상 경력 + 유튜브 채널(독주회 영상) 버튼
- **Dev / Projects 모달**: 기술 스택(Frontend/Backend/Database·Infra) + 실제
  프로젝트 5개(ODYSSEY PLAN, MU:ZIN, GOING, OMIJOY, RunnersHigh) + 교육·자격
  7건
- **Web Design 모달**: 실무 경력 3곳 + 쇼핑몰 웹디자이너 포트폴리오 버튼
- **하단 Contact**: GitHub·이메일(Gmail)·Instagram·Velog·YouTube 글래스모피즘
  아이콘 바

## 대상과 공개 범위
이 페이지는 채용 담당자·협업자에게 무엇을 할 수 있는지 근거와 함께 보여주기
위해 만들었다. 이름과 학력·경력·프로젝트를 검증 가능하도록 실제 정보 그대로
공개한다.

**공개하는 것**
- 이름과 학력·경력
- 실제 프로젝트 결과물과 소스
- 기술 스택과 사용 도구
- 자격·이수 내역
- 공개 연락 채널

**공개하지 않는 것**
- 생년월일 등 개인 식별 정보
- 전화번호·자택 주소
- 희망 연봉
- 협업자의 개인 정보
- 자격증·성적증명서 등 민감 문서 원본

## 강점 — 말이 아니라 근거
About Me 모달에 상황·행동·결과 구조로 작성하고, 각 항목 바로 아래에 해당
근거 폴더로 가는 버튼을 붙였다.

- **꾸준함이 나를 만든다** — 초등학교 관악부부터 이어온 꾸준한 연습 → 콩쿠르
  입상·개인 독주회 개최 → 근거: Music
- **배움에는 유연함이 필요하다** — 코로나로 멈춘 연주 활동을 계기로 디자인·
  개발을 독학 → 자사몰 운영 실무를 거쳐 서비스 기획·구현까지 → 근거: Web
  Design, Dev / Projects
- **좋은 팀은 좋은 성과를 만든다** — 관악부·오케스트라에서 배운 협업 → 실제
  팀 프로젝트(OMIJOY, GOING)에서 역할 완주 → 근거: Dev / Projects

## 디자인 방향
어두운 남색 그라데이션 배경 위에 글래스모피즘(반투명 + blur) 카드를 올린
디자인. 데스크톱 mac 폴더 아이콘 메타포를 사용해 각 주제를 폴더로, 상세
내용을 모달로 구성했다.
- 팔레트: 딥 네이비 그라데이션(#13233f → #628cb4), 코랄 포인트 1색(#ff8a65)
- 타이포: 큰 타이틀(Portfolio)은 세리프 이탤릭(본명조 Source Han Serif, 실패 시
  Fraunces로 대체), 본문은 Pretendard — Google Fonts + jsDelivr CDN 로만 로드,
  별도 빌드 없음
- 버튼·링크·상태 배지 전부 같은 코랄 포인트색과 글래스 pill 스타일로 통일
- 명암비: 본문 텍스트 약 13.7:1, 보조 텍스트 약 10:1, 포인트색 약 7.5:1(모달
  카드 기준) — 모두 일반 텍스트 4.5:1 기준 충족

## 구현한 상호작용
1. **폴더 → 모달**: 폴더를 클릭(또는 Tab 이동 후 Enter/Space)하면 같은 모달
   컴포넌트에 내용만 바뀌어 열린다. 바깥(백드롭) 클릭, X 버튼, Esc 키로 닫히고
   닫으면 포커스가 원래 폴더로 돌아온다
2. **모달 내 근거 이동 버튼**: About Me의 각 강점 아래 "근거 보기" 버튼을
   누르면 모달을 닫지 않고 내용만 해당 폴더로 바뀌며, 포커스가 새 제목으로
   이동해 스크린리더에도 변경이 전달된다
3. **움직임 줄이기 토글**: 헤더의 토글로 배경 애니메이션과 모달 전환 효과를
   끌 수 있고 `localStorage`에 저장된다. `prefers-reduced-motion` 시스템 설정도
   함께 지원한다

## 접근성 대응 내용
- 본문 바로가기(skip link)
- 제목 단계 `h1 → h2 → h3 → h4` 순서 유지, 모달마다 검사 스크립트로 확인
- 키보드 포커스 표시(`:focus-visible`), 네이티브 `<dialog>`로 포커스 트랩
- 링크 텍스트만으로 목적 파악 가능, 반복되는 프로젝트 링크는 `aria-label`에
  프로젝트명 포함, 새 창 링크에 "(새 창)" 표기 + `rel="noopener noreferrer"`
- 색상만으로 구분하지 않음(공개 ＋ / 비공개 × 기호 + 텍스트 병기, 상태 배지에
  문구 포함)
- 본문 대비 4.5:1 이상, 포인트색 3:1 이상 목표 팔레트(위 명암비 참고)

## 검사한 화면 크기
- 1366×768 — 가로 넘침 없음, 첫 화면에 활동명·타이틀·설명·근거 요약·폴더 4개
  가 모두 보인다
- 1920×1080 — 가로 넘침 없음, 첫 화면에 위 항목과 Contact까지 보인다
- 320~390px(모바일) — 세로 1열, 가로 넘침 없음, 폴더가 가운데 정렬된다
- 외부 링크(프로젝트 결과물·소스, 자격 확인, 연결 채널 포함) 전원 HTTP 200
  확인, 브라우저 콘솔 빨간 오류 0개(headless 검사 기준)

## 짧은 확인 방법 4줄
1. 위치: 첫 화면 우측(모바일은 하단)의 폴더 4개 중 아무 폴더나 봅니다.
2. 행동: 폴더를 클릭하거나 Tab 으로 이동한 뒤 Enter 또는 Space 를 누릅니다.
3. 통과 모습: 화면 가운데에 모달이 뜨고 바깥이 어두워지며, 해당 주제의
   실제 내용(경력·프로젝트·근거 링크)이 보입니다.
4. 안 될 때 모습: 눌러도 모달이 뜨지 않거나, 키보드로 실행되지 않거나, 모달이
   메인 화면과 다른 톤으로 어색하게 보입니다.

## AI와 본인의 판단 3줄
1. AI에게 맡긴 일: 시맨틱 HTML/CSS/JS 구현, 모달 컴포넌트화(`<template>` +
   공용 `<dialog>`), 배경 애니메이션과 글래스모피즘 스타일 초안, 링크 상태(200)
   ·명암비·가로 넘침·콘솔 오류 자동 검사, README 정리.
2. 학생이 직접 판단한 일: 공개/비공개 정보 범위와 이름 표기 방식,
   About Me·Music·Dev·Web Design 각 섹션에 넣을 실제 이력과 프로젝트 선택,
   이력서 2종과 자격 인증 캡처를 근거 자료로 제공, 디자인 톤(남색 글래스모피즘)
   방향 지정.
3. AI 제안을 따르지 않은 일: 강점 항목을 모달 하나에 몰아 설명하자는 초안 대신
   상황·행동·결과 뒤에 해당 근거 폴더로 바로 가는 버튼을 각각 붙이는 구조를
   요청해 반영했습니다. 공개 저장소가 확인되지 않은 프로젝트(GOING)의 소스
   링크는 넣지 않고 "준비 중"으로 표기했습니다.

## 검사에서 발견한 실제 결함과 수정 전·후 (T01-C17)

### 결함 1 — 760~1180px 구간에서 폴더가 좌측으로 쏠림 (화면 검사)
- 수정 전: `.desktop-hero`가 `flex-wrap: wrap`만 걸려 있고 `justify-content`가
  없어서, 화면 폭이 좁아 텍스트와 폴더가 한 줄에 안 들어가 줄바꿈될 때 폴더
  줄이 왼쪽으로 붙어버렸다. 세로 구분선도 이 구간에서만 어색하게 남아 있었다.
- 수정 후: `justify-content: center`를 추가하고, 실제로 줄바꿈이 멈추는 지점을
  1110~1150px 사이로 직접 측정해 미디어 쿼리 기준을 1180px로 올렸다. 그 아래
  폭에서는 완전한 세로 중앙 정렬 레이아웃으로, 그 위 폭에서는 안 겹치는
  가로 레이아웃으로 확실히 분리했다.

### 결함 2 — 모바일 레이아웃에서 텍스트와 폴더 사이 빈 공간 발생 (화면 검사)
- 수정 전: 모바일(세로 stack) 모드로 바뀌어도 `.hero-text`에 데스크톱용
  `flex: 1 1 320px`가 그대로 적용되어, 세로 방향에서는 이 값이 높이 성장
  속성으로 작동해 텍스트 블록이 남는 세로 공간을 전부 차지했다. 그 결과 설명
  문단과 폴더 사이에 큰 빈 공간이 생겼다.
- 수정 후: 좁은 화면 전용 미디어 쿼리에서 `.hero-text`와 `.desktop-hero`의
  `flex`를 `none`으로 재설정해 각 블록이 내용 높이만 차지하도록 했다. 텍스트와
  폴더가 지정한 간격(24px)만큼만 떨어지게 됐다.

### 결함 3 — 초기 버전에서 좁은 화면 상단 내비게이션이 겹쳐 잘림 (화면·구조 검사)
- 수정 전: 헤더의 이름·내비게이션·토글 버튼을 한 줄 flex로 배치했는데, 내비게이션
  항목(`.site-nav`)에 `min-width` 제한이 없어 좁은 화면에서 줄바꿈되지 않고
  옆 요소와 겹치며 오른쪽 텍스트가 화면 밖으로 잘려 나갔다.
- 수정 후: `.site-nav`에 `min-width: 0`과 자체 `flex-wrap`을 지정해 필요한
  경우 내비게이션 자체가 줄바꿈되도록 구조를 바꿨다(이후 헤더 자체를 우측
  상단 "움직임 줄이기" 토글 하나로 단순화하며 이 내비게이션은 현재 구조에서는
  제거됐다).
